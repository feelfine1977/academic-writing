# Writing practice: design review

The aim is to help a writer develop a connected draft and transferable writing skills. A better document is useful, but repeatedly accepting model rewrites is not evidence that the writer can independently make the same decisions.

This review combines learning, writing-coaching and interface-design perspectives. It was an AI-assisted analysis of the application and published university guidance, not a consultation with human experts or an assessment of an individual writer.

## The recommended writing loop

1. **Choose one outcome.** Name an idea, connection or example to write. Keep the current draft instead of starting another version from scratch. An optional timer provides a boundary for the session, not a deadline or score.
2. **Write before reviewing.** Rough wording and clearly marked questions are acceptable. Save recovery versions automatically, but distinguish them from deliberate practice checkpoints.
3. **Ask for a reader's response.** Identify specific effective writing and one useful next action. Separate an unclear argument from a language correction or optional stylistic preference.
4. **Make an independent revision.** Record what changed or why existing wording should remain. Shortening, clarifying and preserving a successful passage can all represent useful work.
5. **Use a worked example when needed.** After drafting and revising, the writer may request a model for a short selected passage. Explain the sentence jobs, connection and meaning preserved. The writer can adapt the example and then try the next related passage independently.
6. **Leave a restart point.** Save a concrete next action with the section so it is available on another device. Continuing a sustainable practice matters more than extending every session.

Diagnosis and clarification should remain available from the start. A worked example should not become a prize for clicking Save repeatedly. Prior work outside the app can be acknowledged explicitly; the application cannot determine authorship from typing speed, pasted text or word counts.

## Interface decisions

- Keep the current writing goal and editor prominent. Put source browsing, older feedback and optional language alternatives behind deliberate choices.
- Make **Work on one point myself** and **Keep this and continue writing** available directly from feedback.
- Reuse a completed reading when the submitted text, question and relevant context are unchanged. Another stochastic response is not automatically a better assessment.
- Preserve one current manuscript and its recoverable history. Avoid presenting every autosave as a new writing achievement.
- Store intentions, restart notes, review snapshots and deliberate checkpoints in the private paper folder. A live timer can stay device-local; it should not resume unexpectedly on another computer.
- Treat checkpoint origin as an explicit self-report. Model-assisted work remains useful and is retained, but is not counted as an independent drafting attempt.
- Permit stopping, breaks, untimed work and changes of strategy without losing progress or imposing a penalty.

## Evidence informing the design

Carnegie Mellon's Eberly Center describes the value of achievable learning goals, targeted feedback, repeated practice and reflection on one's approach. These principles support a small writing goal followed by a revision and reflection, rather than constant unstructured feedback. They do not establish an optimal timer duration or a universal number of attempts. [Learning principles](https://www.cmu.edu/teaching/principles/learning.html)

UNC's Writing Center recommends breaking writing into manageable periods, allowing imperfect early drafts and leaving a point from which to restart. It also describes how excessive preparation or repeatedly revising one part can displace progress on the rest. These recommendations support a small start and a visible next action. [Procrastination guidance](https://writingcenter.unc.edu/tips-and-tools/procrastination/)

Harvard's Writing Center explains transitions through the relationship between ideas, including deliberate repetition of a key term and making the logical connection explicit. This supports checking what each sentence gives the next before searching for synonyms or inserting connector words. [Transitions](https://writingcenter.fas.harvard.edu/transitions)

The interface choices above are design inferences from this guidance. They are not a validated treatment for attention difficulties, a guarantee of motivation, or a requirement that every writer follow the same routine.

## Checks that matter

An unchanged scaffold, repeated save or duplicate synced file must not create another practice attempt. A shorter deliberate revision must remain eligible. Model suggestions must be optional, limited to the selected passage and reversible. Navigating during a save or checkpoint request must not mix sections or erase later edits. A positive reading should allow the writer to move forward without another assessment. Private examples, drafts, feedback and paper-specific guidance must remain outside the public application repository.
